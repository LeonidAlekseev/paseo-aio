# Domain documentation

This is a single-context repository.

Before researching domain terms or making architecture changes, read the root
`GLOSSARY.md` if it exists and relevant decisions under `docs/adr/`.
If absent, continue normally. Create glossary entries and ADRs only when real
terms or decisions need recording; no empty scaffolding is required.

Use glossary names in specs, tickets and code discussions. If a proposed change
contradicts an ADR, identify the decision and explain the conflict before
replacing it.
