## Стек разработки

- Процесс программирования ведёт Pocock (mattpocock-skills). Paseo — только транспорт: worktree, запуск исполнителей по профилям (`list_profiles`), связь с ними.
- Точка входа для задач разработки, сформулированных словами (фича, рефакторинг, баг, ревью, исследование, разбор issues), — скилл `orchestrate`.
- Реестр задач — GitHub issues. Статусы — метки triage; `ready-for-agent` ставится только после явного согласия пользователя.
- Код пишут только модели Claude. Ponytail работает всегда. Перед сдачей работы — `/ponytail-review` на свой дифф.
- Навигация по коду: сначала CodeGraph, потом grep и чтение файлов.

## Роли и запреты
- Субагентов для ролей Pocock (implementer, merger, exploration, reviewer, research) запускает только оркестратор и только через Paseo по скиллу `pocock-paseo`. Исполнитель своих субагентов не создаёт.
- Не вызывать: `implement-spec` в обход `orchestrate`, `research` (исследования идут по профилям `code-research` / `web-research`), `handoff` (вместо него `paseo-handoff`). `code-review` вызывает только оркестратор.
- Исполнитель не меняет issues, метки и файлы вне scope тикета; находки вне scope перечисляет в отчёте.

## Ревью
Приоритет при конфликте замечаний: тесты > спека/тикет > Ponytail > advisor/arbiter.
Один раунд исправлений на ревью. Повторный спор — профиль `arbiter`; не разрешён — решает пользователь.
Отклонённое замечание — одна строка: что отклонено и по какому пункту приоритета.

## Git
Целевая ветка `dev`, PR только через merge commit, без rebase и force push. В `main` — только при релизе.
Тесты не ослаблять и проверки не удалять ради зелёного CI. Не заявлять о merge, PR или пройденных проверках без фактического подтверждения.
